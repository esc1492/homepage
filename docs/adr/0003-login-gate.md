# ADR-0003: 로그인 게이트는 마크업이 선언하고 세션 하나로 판정한다

- **상태**: Accepted (2026-10-18)
- **관련**: ADR-0002, `GLOSSARY.md`

## 맥락

`index.html`의 로그인 게이트는 두 가지를 동시에 갖고 있었습니다.

- 인증이 필요한 대상은 **URL 문자열 리터럴**로 판정했습니다:
  `url==='/chat'||url==='/ocr'||url==='/voca'`.
- 로그인 여부는 `localStorage.loggedIn`으로 판정했습니다.

그 결과 링크를 추가할 때 마크업과 문자열 목록 **두 곳**을 고쳐야 했고, 한쪽만 고치면 게이트가
조용히 죽었습니다. `/album`은 인증이 필요한 앱인데 목록에서 빠져 있었고, 쿼리스트링이 붙은
URL은 문자열 비교를 통과했습니다. `CLAUDE.md`는 이 구조를 재발 함정으로 세 번 기록하고 있었습니다.

## 결정

1. 인증이 필요한 링크는 마크업에서 **`data-auth`** 로 선언합니다.
2. 게이트 판정은 **실제 세션 하나** — `window.session.getSession()` — 만 봅니다.
3. `/album`은 **게이트하지 않습니다.** 앨범은 자체 로그인 화면(AuthPage)을 갖고 있습니다.
4. URL 문자열 목록은 제거합니다.
5. 보안 경계는 그대로 API 함수의 401/403입니다. 게이트는 UX입니다.

## 근거

- **마크업이 진실이 됩니다.** 링크를 추가할 때 `data-auth`를 붙일지만 결정하면 되고,
  별도 목록을 동기화할 위험이 없습니다.
- **상태 소스가 하나가 됩니다.** ADR-0002로 세션 module이 `localStorage.loggedIn`의 단독
  쓰기 지점이 되었으므로, 게이트가 세션을 보면 플래그와 세션이 갈라질 여지가 없습니다.
- **앨범을 게이트하면 UX만 나빠집니다.** 앨범은 로그인하지 않아도 자체 AuthPage로 진입할 수
  있는 앱입니다. 홈에서 한 번 더 막으면 경로만 늘어납니다.
- **데이터 속성은 마크업의 관심사**입니다. `data-link`가 목적지를 선언하듯 `data-auth`가
  인증 요구를 선언합니다.

## 결과

- 링크 추가는 `data-link`와 (필요하면) `data-auth`만 쓰면 됩니다.
- 게이트는 세션 module 초기화 이후에 유효합니다. 클릭 시점에는 `DOMContentLoaded` 초기화가
  이미 끝나 있으므로 실사용에 문제가 없습니다.
- `CLAUDE.md`의 “게이트가 두 곳” 경고는 새 방식 설명으로 교체했습니다.
